# Data format

The package ships two JSON files for use outside JavaScript, typically by a port to another
language:

- `data/units.json` — every table the functions read.
- `data/test-vectors.json` — inputs and expected outputs for every public function.

Together they are the contract: a port that loads `units.json`, follows the rules below and passes
every vector behaves like this package. Both are generated by `npm run build` (`units.json` from the
built code, `test-vectors.json` from [`test/vectors.json`](../test/vectors.json)), so they never
disagree with the TypeScript. They are versioned with the package: take them from the same
release, from the npm tarball (`package/data/`) or from `cooking-units/data/*.json` in JavaScript.

Each file has a `schema` number. It changes when a field is removed or changes meaning; new fields
can appear without one. `version` is the package version the file was built for.

## Reading the files

- **Order is data.** Object keys and array items are written in a fixed order, and some results
  depend on it (listed below). Read objects into insertion-ordered maps: `LinkedHashMap`,
  kotlinx.serialization's `JsonObject` and Jackson all keep it.
- **Every number is an IEEE-754 double**, written in the shortest form that reads back as the same
  double. Parse them all as doubles, including the ones that look like integers (`1000`), never as
  `Float` or `BigDecimal`.
- **Strings are compared exactly**, code unit for code unit. Nothing is Unicode-normalized: `càs`
  written with a combining accent (`ca\u0300s` in the vectors) is a different string, and is not
  recognised. Invisible characters are written as `\u` escapes so they can be seen.

## `units.json`

```json
{
  "schema": 1,
  "version": "0.3.0",
  "languages": ["en", "nl", "fr", "de", "es"],
  "units": { "ml": { "group": 0, "factor": 1 }, "…": "…", "piece": null },
  "conversionGroups": [[{ "unit": "ml", "factor": 1 }, { "unit": "cl", "factor": 10 }, "…"], "…"],
  "aliases": { "en": { "cup": ["cups"], "…": "…" }, "nl": { "tbsp": ["el", "eetlepel", "eetlepels"] } },
  "display": { "en": { "cup": { "one": "cup", "other": "cups" } }, "fr": { "piece": null } },
  "unicodeFractions": { "¼": 0.25, "½": 0.5, "⅓": 0.3333333333333333, "…": "…" }
}
```

| Field | What it is | Order |
| --- | --- | --- |
| `languages` | The language codes with a vocabulary (`LANGUAGES`). | Significant: the alias map is built in this order. |
| `units` | Every canonical unit, with what `lookupUnit` returns for it: `{ group, factor }`, or `null` for a countable unit. Derived from the fields below; there for convenience. | Convertible units by group, then countable ones. |
| `conversionGroups` | Units that can be summed with each other. `factor` is relative to the group's base unit (factor 1). A unit's group is its index in this array. | Significant: groups by index, units smallest to largest. |
| `aliases` | Per language, canonical unit → the ways that language writes it, most idiomatic first (`LANGUAGE_ALIASES`). All lowercase and trimmed. English lists plurals and spelled-out forms only. | Significant: the first form is what `localizeUnit` writes, and `aliasesOf` follows this order. |
| `display` | Per language, canonical unit → `{ one, other }`: the singular and plural `formatUnit` writes, or `null` where the language writes no unit (`UNIT_DISPLAY`). Only some languages have a table. | Not significant. |
| `unicodeFractions` | Single-character fractions → their value. | Not significant. |

### The alias map

`normalizeUnit` looks written forms up in one flat map (`UNIT_ALIASES`). Build it by walking
`languages` in order, and within each language `aliases` in order, adding `form → canonical unit`.
A form that is already in the map keeps its first unit (the package's tests guarantee no form is
claimed twice, so this never happens with the shipped data).

## Behaviour

What each function does with that data. Where this and a vector disagree, the vector is right.
Wherever a parameter can be null, JavaScript's `null` and `undefined` behave the same.

**`normalizeUnit(unit)`** — `null` if `unit` is null or empty. Otherwise lowercase it, then trim
it; `null` if that leaves nothing. Return the alias map's unit for it, or the lowercased, trimmed
string itself.

**`localizeUnit(unit, language)`** — `c = normalizeUnit(unit)`; `null` if that is null. For `en`,
return `c`. Otherwise the first form in `aliases[language][c]`, or `c` when there is none.

**`aliasesOf(canonicalUnit)`** — every form in the alias map whose unit equals `canonicalUnit`
exactly, in map order. The argument is not normalized.

**`lookupUnit(unit)`** — `{ group, factor }` from `conversionGroups`, or `null` when `unit` is null,
empty, or in no group. The argument is not normalized.

**`areCompatible(a, b)`** — both `lookupUnit(normalizeUnit(…))` are non-null and have the same group.

**`convertUnit(amount, from, to)`** — `v = parseAmount(amount)`; `null` if NaN, or if the two
normalized units are not in the same group. Otherwise `(v * from.factor) / to.factor`, in that
order.

**`parseAmount(value)`** — a number is returned as is; null gives NaN. A string is trimmed, then:

1. The whole string is a key of `unicodeFractions`: its value.
2. It ends with a key of `unicodeFractions`: take what comes before, trimmed. Empty counts as 0;
   otherwise read it with the parseFloat rule below. If that is not NaN, return it plus the
   fraction; if it is, go on to step 3.
3. It matches `^(\d+)?\s*(\d+)/(\d+)$` (a greedy, backtracking regex; `\d` is ASCII 0–9) and the
   last number is not 0: `whole + numerator / denominator`, with a missing whole as 0.
4. Otherwise the parseFloat rule.

The **parseFloat rule** is JavaScript's `parseFloat`: skip leading whitespace, then read the longest
prefix matching `[+-]?(Infinity|(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?)`, NaN if there is none. Text after
the number is ignored, so `"2 cups"` is 2, `"1-2"` is 1 and `"1,5"` is 1. This differs from
`toDouble()` on the JVM, which rejects trailing text and accepts `"NaN"`, hex and a `d`/`f` suffix.

**`formatAmount(value, decimals = 2)`** — when `value` is a whole number, its integer digits with no
decimal point (`3`, not `3.0`). Otherwise JavaScript's `toFixed(decimals)`: round the *exact* binary
value to `decimals` places, ties away from zero, so 1.005 (really 1.00499…) gives `1.00` and 0.125
gives `0.13`. On the JVM that is `BigDecimal(value).setScale(decimals, RoundingMode.HALF_UP)`, not
`String.format`, which rounds a shorter decimal form; then `toPlainString()`. NaN gives `NaN` and
the infinities `Infinity` and `-Infinity`. Two cases no vector covers: a small negative can round
to `-0.00` in JavaScript, and values of 1e21 and above use an exponent.

**`bestDisplayUnit(baseAmount, groupIndex)`** — walk the group from its largest unit down and return
the first where `baseAmount / factor >= 1`, as `{ amount: baseAmount / factor, unit }`. If none
fits, the smallest unit, computed the same way. An index with no group gives
`{ amount: baseAmount, unit: "" }`.

**`sumQuantities(quantities)`** — for each quantity in order: `u = normalizeUnit(unit)`, and its
bucket is `u`'s group if it has one, otherwise `u` itself (null for no unit). Buckets keep the order
in which they were first seen. `v = parseAmount(amount)`: NaN adds 1 to the bucket's `unmeasured`,
anything else adds `v * factor` (grouped) or `v` (not grouped) to its total, starting from 0, in
input order. A grouped bucket is then written with `bestDisplayUnit`; any other keeps `u` as its
unit.

**`formatUnit(unit, language, amount = null)`** — `c = normalizeUnit(unit)`; `null` if that is
null. If `display[language][c]` is `null`, return `null`. If there is no entry, return
`localizeUnit(c, language)`. Otherwise `other` when the amount is plural and `one` when not. The
amount is plural when, for a string, the part after the last `-` or `–` (with any whitespace
around it) — or for a number, the number itself — parses with `parseAmount` to more than 1, or to
2 or more for `fr`. NaN is not plural.

**Whitespace and case.** Trimming is JavaScript's `trim()`: it removes Unicode space separators
(including U+00A0 no-break space), tab, line breaks, U+2028, U+2029 and U+FEFF. Kotlin's `trim()`
differs: it keeps U+FEFF and also removes U+001C–U+001F. `\s` in the regexes is JavaScript's and
matches that same set; Java's `\s` matches ASCII whitespace only, so write the set out as a
character class. Lowercasing is locale-independent (`lowercase()` in Kotlin, never with a Turkish
locale).

## `test-vectors.json`

```json
{
  "schema": 1,
  "version": "0.3.0",
  "functions": {
    "formatUnit": {
      "params": ["unit", "language", "amount"],
      "cases": [
        { "args": ["clove", "fr", "1½"], "expected": "gousse", "note": "French is plural from 2, other languages above 1" },
        { "args": ["pinch", "nl"], "expected": "snufje" }
      ]
    }
  }
}
```

`functions` has one entry per public function, keyed by its name. `params` names its parameters
in order; each case calls it with `args` in that order and expects `expected`. `note`, when present,
says what the case is about.

- **`null`** stands for JavaScript's `null` and `undefined` alike, in `args` and in `expected`.
- **Missing trailing arguments** take the parameter's default: `decimals` is 2, `amount` is null.
- **NaN and infinities** are written as `{ "number": "NaN" }`, `{ "number": "Infinity" }` and
  `{ "number": "-Infinity" }`, since JSON has no literal for them. An object with only a `number`
  key is never anything else.
- **Numbers compare exactly.** The expected values are the doubles the TypeScript computes. A port
  that does the same double operations in the same order, as described above, gets the same bits:
  compare with `==` (and NaN with NaN), not with a tolerance. A vector that fails by a last digit
  points at an operation done differently or in another order.
- **Objects compare by key and value**; key order does not matter. Arrays compare in order.

The TypeScript runs the same file in `test/vectors.test.ts`.
